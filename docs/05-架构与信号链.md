# 05 架构与信号链

写给要读代码或改代码的人。**本文件描述设计意图与数据流；具体参数值见 [02-音色与混音.md](02-音色与混音.md)**，语法细节见 [01-格式规范-tms.md](01-格式规范-tms.md)。

## 1 分层

```
score/*.tms                纯文本乐谱（内容）
      │
      │  score.py            解析：文本 → Score 数据模型（只解析，不渲染）
      ▼
   Score ──────────────► validate.py    静态校验：错误 / 警告（不渲染也能发现问题）
      │
      │  render.py           调度：Score → 分轨缓冲 → 效果 → 总线 → 波形
      ├──► voices.py        有音高音色（加法合成 + FM）→ 波形
      ├──► drums.py         打击乐（正弦/噪声 + 包络 + 频域滤波）→ 波形
      └──► effects.py       混响/延迟/合唱/EQ/侧链/限幅/声场（纯数组函数）
      ▼
   WAV 波形 ──► analyze.py    数值体检：电平/动态弧/频段/削波/相关度
           ──► visualize.py  钢琴卷帘 PNG
           ──► flac.py       无损压缩（自带编解码）
```

**没有反向依赖**：`voices.py`/`drums.py` 不知道 Score 的存在，只接受「频率列表 + 时长 + 力度」；
`effects.py` 不知道音色的存在，只接受数组。所有耦合集中在 `render.py`。

## 2 数据结构

| 类型 | 位置 | 含义 |
|---|---|---|
| `Instrument` | `score.py` | 声部：音色、增益、声场、混响送出、和弦展开方式 |
| `Event` | `score.py` | pattern 内的一个记号：音高/和弦/鼓件 + 起拍 + 时值 + 力度 |
| `Pattern` | `score.py` | 乐句单元，挂在某个 track 下；**长度 = 末事件的「起拍+时值」** |
| `Placement` | `score.py` | 编排条目：把 pattern 放到若干小节范围，带 transpose/gain/pan/octave |
| `Score` | `score.py` | 以上全部 + 速度/调性/摇摆/随机种子/段落标记 |
| `Hit` | `render.py` | 展开后的**一次发声**：已算好绝对拍位置、MIDI 音组、有效增益与声场 |

`expand()` 是唯一的「语义展开」处：小节范围 × pattern 循环 → 和弦按 `chord=` 模式拆成琶音/柱式 → 摇摆与人性化抖动 → 绝对拍位置。它不产生任何波形，因此可以只看不渲染（`check` 与钢琴卷帘都复用它）。

## 3 渲染流水线

```
1. expand(score)                     → hits，按起始拍排序
2. 分配缓冲                          → 每个「声部 × 有效声场位置」一条 (n,)
3. 逐 hit 合成
     ├─ 有音高：查缓存 → 未命中才调用 voices.render_hit
     │            （缓存键＝音色+音高组合+时值+量化力度）
     ├─ 打击乐：直接调用 drums.gen_drum（每次独立随机，保证鼓点不机械重复）
     └─ × vel^1.5 × instrument.gain × placement.gain，落到缓冲对应偏移
     └─ kick 额外累加进 kick_key（供侧链键控）
4. 分轨处理                          → chorus（若有）
5. 送出                              → 混响总线 / 延迟总线
6. 混响：合成 IR → 重叠相加 FFT 卷积 → 0.55 → 180 Hz 高通
   延迟：0.75 拍乒乓反馈延迟 → 320 Hz–5.2 kHz 带通
7. 汇总                              → 逐缓冲：侧链衰减（若有 duck）→ 按 pan 分配到左右
8. 母带链                            → HP 28 → EQ(4 段) → 胶水压缩
                                       → RMS 归一 → 120 Hz 以下单声道 → 加宽
                                       → 前视限幅 → 真峰值兜底
9. 写盘                              → 16-bit PCM + TPDF 抖动
```

每一步都可在 `render.py::render_score` 里顺序读到，没有隐藏的全局状态。

## 4 三个关键设计

### 4.1 加法合成，而不是「振荡器 + 滤波器」

纯 Python 逐样本跑 IIR 滤波器（biquad）在 8.5M 采样 × 多声部规模下不可行。改用**分音级加法合成**：

- 每个分音 `k` 有固定频率 `f_k` 与初相，波形 `sin(2π f_k t)`；
- 音色亮度由「随时间变化的低通响应」直接乘在**每个分音的幅度包络**上：`fc(t)² / (fc(t)² + f_k²)`；
- 结果天然无混叠（只合成到 Nyquist 以下的分音），且滤波器扫频不需要任何循环；
- 代价是分音数量有限（各音色 8–26 个），高频细节靠 1/k 谱型补足。

具体实现在 `voices.additive_layer()`：按 16k 采样分块，块内用 `(K, m)` 矩阵一次算完 `sin` 与增益，避免 Python 循环。

### 4.2 两套归一化

不同音色的**峰均比差 20 dB**（拨弦类衰减快、峰值高；铺底类持续、峰值低）。若统一按峰值归一，拨弦会响到削波；若统一按 RMS 归一，拨弦会被峰值兜底压小、整条旋律消失。所以：

- `norm="rms"`：按「40 ms 滑动 RMS 的 88 分位」归一化 —— 铺底、弦乐、空气层、Sub；
- `norm="peak"`：按峰值归一化 —— 拨弦、尼龙、电钢、钟琴、八音盒；
- 两者都带 0.9 峰值兜底，保证任何单次触发都不削波。

### 4.3 确定性

同一乐谱 + 同一 `seed` → **逐字节相同**的 WAV。做法是：所有随机数都来自 `np.random.default_rng([seed, 序号, 常量])`，序号在展开顺序里是确定的，绝不使用系统时间或全局随机状态。写盘时的 TPDF 抖动也用固定种子。

> 注意：有音高音色的**渲染缓存**让「第 n 次未命中」参与随机种子。因此改动乐谱的无关部分，会让后面某些音的初相变化 —— 仍然完全确定，但不要指望「改 A 段不影响 B 段的波形」。这是有意的取舍（缓存把整曲渲染从 ~28 分钟压到 ~80 秒）。

## 5 性能

| 阶段 | 整曲耗时（实测，Python 3.12 / numpy 2.3 / Ryzen 7 7435H） |
|---|---|
| 解析 + 校验 | < 0.5 s |
| 波形合成 | ~75 s（启用缓存后；关闭缓存约 28 分钟） |
| 混响 + 延迟 + 母带 | ~5 s |
| 钢琴卷帘 PNG | ~1 s |
| FLAC 编码（64 MB→ 22 MB） | ~28 s |

缓存的意义：乐谱里同一和弦、同一琶音音型会重复出现上千次，按「音色+音高组合+时值+量化力度」缓存后，实际只合成几百个不同的波形。

## 6 边界与已知限制

- **只支持 4/4**：`meter` 写别的值会报错（解析器里显式拦住，不静默忽略）。
- **不支持变速**：`tempo` 全曲恒定。
- **不支持音频输入**：没有采样、没有外部素材导入通道。
- **和弦展开是「机械的」**：`arp-up` 只是循环和弦音，不做声部进行优化；想要真正的织体请写显式音名。
- **FLAC 解码器只用于自检**：逐样本 Python 解码，整曲要 1–2 分钟，不是播放器实现。
- **混响 IR 是程序生成的噪声**，不是真实空间的脉冲响应；听感偏「合成」，好处是完全可复现且零素材。
