# 07 扩展与工作流

## 1 加一个音色（patch）

以「一个带延音的方波主奏」为例：

```python
# 1) tmskit/voices.py 里写生成器：只接受「频率列表 + 时长 + 力度」，返回单声道 float64
def gen_square_lead(freqs, dur, vel, sr, rng):
    rel = 0.5
    n = _hold_len(dur, rel, sr)
    ratios, amps = _partials_saw(20, (0.0,), tilt=0.5)   # tilt<1.5 取全部奇偶次；实际方波只取奇次见下
    ratios, amps = _partials_saw(20, (0.0,), tilt=2.0)   # 三角谱型，按需替换
    env = adsr(n, sr, attack=0.02, decay=0.3, sustain=0.7, release=rel, hold=dur)
    fc = _cutoff_curve(n, sr, 3800.0, 2200.0, 0.4)
    return additive_layer(freqs, n, sr, ratios, amps, env, fc, rng)

# 2) 注册（nominal_db 的含义取决于 norm）
PITCHED_PATCHES["square-lead"] = PatchSpec(
    "square-lead", "pitched", 40, 96, -22.0, "方波主奏（rms 归一）", gen_square_lead, "rms"
)
```

然后：

```powershell
python -m tmskit patches                    # 确认已出现在列表里
python -m tmskit check score/tide-end.tms   # 校验器会检查音域与 patch 是否存在
```

**必须同时做**：在 [02-音色与混音.md](02-音色与混音.md) §1 的表格里登记一行（配方、包络、归一方式、推荐音域）。
**注意**：`norm="peak"` 适合一次性击发类音色，`norm="rms"` 适合有稳定延音的；选错会导致混音配平整体偏移（见 [06](06-关键决策与踩坑记录.md) D2）。

## 2 加一条 TMS 语法

固定四步，缺一不可：

1. 改 [01-格式规范-tms.md](01-格式规范-tms.md)：新增语法必须先在规范里有定义（含取值、默认值、错误条件）。
2. 改 `tmskit/score.py`：在解析器里实现，**错误要带行号**（用 `ScoreError` 或往 `problems` 里追加）。
3. 改 `tmskit/validate.py`：补上对应的错误/警告规则，并在错误信息里说清「哪个文件哪一行、错在哪、可用值是什么」。
4. 改 `tests/test_tmskit.py`：加一个「合法输入能过、非法输入报错」的用例。

如果新语法影响发声，还要改 `render.py::expand()` 或 `_chord_sequence()`。**别把语义散落在多个模块**：解析归 `score.py`，语义展开归 `expand()`，波形归 `voices/drums`。

## 3 加一个效果

`tmskit/effects.py` 里所有函数必须是**无状态纯数组函数**（输入数组 → 输出数组），不读全局、不写文件。然后：

1. 在 `render.py::render_score` 的对应环节调用它（分轨 / 送出 / 总线 / 母带，四个插入点）；
2. 参数若应由乐谱控制，就在 `score.py` 的 `instrument` 允许参数里加，并在 [01](01-格式规范-tms.md) §3 登记；
3. 参数若是全局固定的，写进 [02](02-音色与混音.md) §3 的表；
4. 渲染一遍，确认 `analyze` 的门禁仍然全过。

## 4 写一首新曲

推荐顺序（这首《潮汐尽头》就是这么来的）：

1. **定骨架**：速度、调性、段落表（每段多少小节）、动态弧（哪段最轻、哪段最响）。先在 `docs/` 里写下来。
2. **定和声**：整曲只用 2–3 组进行，每组 4–8 小节。每换一组，该组的 8 小节版本要在 `pad.*`、`keys.*`、`arp.*`、`bass.*`、`strings.*` 各写一份同名 pattern（名字带进行名，如 `pad.verse`）。
3. **写动机**：2 小节一句、4 小节一乐段。写成 `lead.M`；变奏另起 `lead.M2`/`lead.M3`，**每次只改一项**（换尾 / 移位 / 改节奏）。
4. **铺编排**：`arrange` 里按 8 小节为单位增减声部，别让所有层同进同出。
5. **跑校验**：`python -m tmskit check score/xxx.tms`，先把错误清零，再逐条看警告（调外音、强拍非和弦音、pattern 超范围通常都是真问题）。
6. **渲染 + 体检**：`python -m tmskit all score/xxx.tms -o out`，重点看三处：整体 RMS 是否落在 −18…−12、限幅衰减是否 ≤3 dB、段落 RMS 是否有 4–6 dB 的单峰落差。
7. **看卷帘图**：`python -m tmskit roll`，检查有没有空洞小节、有没有某段厚得糊成一团。
8. **配平**：看 `render` 打出的「分轨 × 分段 RMS」表，按 [02](02-音色与混音.md) §4 的相对关系调 `instrument` 行的 `gain` 与 `arrange` 条目的 `gain=`（两者相乘）。
9. **收尾**：`flac` 导出、`roll` 出图、更新 README 的试听信息。

最小可用起点可以直接抄 [../score/example.tms](../score/example.tms)（4 小节、5 声部、带鼓组网格）。

## 5 验收清单（每次改动后照做）

```powershell
python -m tmskit check  score/tide-end.tms        # 错误必须为 0
python -m tmskit all    score/tide-end.tms -o out # 渲染 + 体检 + 出图
python -m unittest discover -s tests -t .         # 单元测试
python -m tmskit flac   out/tide-end.wav -o out/tide-end.flac --verify
```

| 检查项 | 门禁 | 谁检查 |
|---|---|---|
| 语法与语义 | 错误 0 条 | `check` |
| 整体 RMS | −18 … −12 dBFS | `analyze` |
| 真峰值 | ≤ −1.0 dBTP | `analyze` |
| 削波样本 | 0 | `analyze` |
| 限幅衰减 | ≤ 3 dB（本曲 1.0） | `render` 输出 |
| 段落动态差 | ≥ 3 dB（本曲 5.6） | `analyze` |
| 声道相关度 | ≥ 0.2（本曲 +0.59） | `analyze` |
| 直流偏移 | ≈ 0 | `analyze` |
| 确定性 | 两次渲染逐字节一致 | 手工跑两次比对哈希 |
| FLAC | 往返逐字节一致 | `flac --verify` |

## 6 开源 / 发版

仓库已经准备好（`LICENSE`、`LICENSE-MUSIC`、`.gitignore`、README 里的协议与素材来源）。要发布到 GitHub：

```powershell
cd D:\test
git add -A
git commit -m "feat: tmskit 文本乐谱→电子音工具链 + 原创作品《潮汐尽头》"
git branch -M main
git remote add origin https://github.com/<你的用户名>/llm-music-lab.git
git push -u origin main
```

- 仓库里**包含** `out/tide-end.flac`（22 MB，无损成品）与钢琴卷帘图，访客 clone 下来就能听；
- **不包含** `out/tide-end.wav`（32 MB，可由乐谱 90 秒重新生成），规则写在 `.gitignore` 里；
- 如果你的仓库接受不了 22 MB 的二进制，把 `out/*.flac` 也加进 `.gitignore`，改用 GitHub Releases 上传音频；
- 协议划分与第三方依赖说明见 [08-许可与素材来源.md](08-许可与素材来源.md)。
